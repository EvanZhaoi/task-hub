# 27 - 投标与选标邮件通知

## 1. 本章目标

第一期增加两个邮件通知动作：

1. 有人提交投标后，通知任务发布者。
2. 发布者选标成功后，通知中标负责人和全部协作成员。

本章只实现邮件通知，不新增站内消息表、消息队列、Notification 表或复杂通知中心。

## 2. 最终效果

### 2.1 新投标通知

```text
开发者提交投标
    ↓
投标事务成功提交
    ↓
解析任务发布者邮箱
    ↓
发送“收到新投标”邮件
```

邮件包含任务标题、投标人、金额、承诺交付日期和任务详情链接。

### 2.2 中标通知

```text
发布者完成选标
    ↓
选标事务成功提交
    ↓
读取中标 BidMember
    ↓
分别通知 OWNER 和 COLLABORATOR
```

每个成员收到独立邮件，避免通过 To/CC 暴露其他成员邮箱地址。

## 4. 生成基础文件

命令执行目录：项目根目录。

```bash
# 生成统一邮件通知 Service 骨架。
php artisan make:class Services/TaskEmailNotificationService --no-interaction

# 生成两封 Mailable 和对应 Markdown Blade 模板。
php artisan make:mail BidSubmittedMail --markdown=mail.tasks.bid-submitted --no-interaction
php artisan make:mail BidSelectedMail --markdown=mail.tasks.bid-selected --no-interaction
```

命令只生成 Laravel 标准文件结构，业务字段、中文内容和通知时机仍需手工实现。

## 5. 为什么不使用数据库 Notification

第一期需求明确为邮件通知，当前没有站内消息列表、未读状态或消息中心需求，因此不创建：

- `notifications` 表。
- `notification_recipient` 表。
- Laravel database notification migration。
- Outbox 或消息队列。

如果后续需要站内未读消息，再作为独立版本设计，不能为了未来可能性提前扩大第一期范围。

## 6. 邮箱来源

### 6.1 任务发布者

新任务发布时，把当前 SSO 用户邮箱放进 `created_by_snapshot.email`。JSON 快照不需要修改数据库字段。

历史任务可能没有邮箱快照，因此按以下顺序解析：

```text
created_by_snapshot.email
    ↓ 没有或格式非法
PersonnelClient 根据 created_by 工号查询 eibEmail
    ↓ 仍然没有
记录 warning，跳过邮件
```

### 6.2 中标成员

选标后的收件人来自中标 `bid_member`：

- `OWNER` 收到“负责人”通知。
- `COLLABORATOR` 收到“协作成员”通知。

邮箱通过 `PersonnelClient` 的本据点人员列表读取 `eibEmail`，不接受前端提交邮箱。

## 7. 事务与邮件发送顺序

邮件不能放在数据库事务内：

```php
// 先完成投标的数据库事务。
$bid = DB::transaction(function (): Bid {
    // 创建 Bid、成员、附件和事件。
});

// 事务提交成功后再发邮件。
// SMTP 失败不会撤销已经成功的投标。
$this->emailNotifications->notifyBidSubmitted(
    task: $task,
    bid: $bid,
    bidder: $user,
    accessToken: $accessToken,
);

return $bid;
```

如果在事务内发送邮件，会产生两个问题：

1. SMTP 延迟会延长数据库行锁时间。
2. 邮件已经发出后事务仍可能回滚，用户会收到不存在的业务结果。

选标采用同样顺序：先提交选标事务，再读取中标成员并发送邮件。

## 8. 邮件失败策略

`TaskEmailNotificationService` 捕获人员接口、模板和 SMTP 异常，记录以下安全上下文：

- task_id。
- 收件人工号。
- 通知类型。
- 异常类型和错误消息。

日志不记录：

- accessToken。
- clientSecret。
- 完整外部接口响应。

通知是业务动作后的辅助能力。邮件失败不能让用户看到“投标失败”或“选标失败”，因为核心数据库事务已经成功。

## 9. Mailable 设计

`BidSubmittedMail` 只接收模板需要的数据：

```php
public function __construct(
    public readonly string $taskTitle,
    public readonly string $taskUrl,
    public readonly string $bidderName,
    public readonly string $amount,
    public readonly string $deliveryDate,
) {}
```

不直接把整个 Eloquent Model 传给模板，可以减少模板意外查询关系或暴露无关字段。

第一期没有实现 `ShouldQueue`。当前 `QUEUE_CONNECTION=sync`，邮件在请求结束前同步发送，但设置了 SMTP 超时并采用失败不回滚策略。

## 10. 环境变量

开发环境默认使用日志驱动：

```dotenv
# 邮件内容写入 storage/logs/laravel.log，不会真实发送。
MAIL_MAILER=log
MAIL_FROM_ADDRESS="hello@example.com"
MAIL_FROM_NAME="${APP_NAME}"
```

接入公司 SMTP 后使用：

```dotenv
# 邮件中的“查看任务详情”链接使用 APP_URL 生成，部署时必须填写真实 TaskHub 地址。
APP_URL=https://taskhub.example.com
MAIL_MAILER=smtp
MAIL_SCHEME=null
MAIL_HOST=公司提供的SMTP地址
MAIL_PORT=公司提供的端口
MAIL_TIMEOUT=5
MAIL_USERNAME=公司提供的用户名
MAIL_PASSWORD=公司提供的密码
MAIL_FROM_ADDRESS=公司批准的发件地址
MAIL_FROM_NAME="TaskHub"
```

修改 `.env` 后执行：

```bash
# 清除配置缓存，让新的 SMTP 参数生效。
php artisan config:clear
```

真实 SMTP 地址、端口、账号和发件地址必须由公司邮件管理员确认，不能提交到 Git。

## 11. 与 Spring Boot 的概念对照

| Laravel | Spring Boot 中相近概念 |
| --- | --- |
| `Mailable` | 邮件 DTO + `JavaMailSender` 模板参数 |
| Markdown Blade | Thymeleaf / FreeMarker 邮件模板 |
| `Mail::to()->send()` | `JavaMailSender.send()` |
| `config/mail.php` | `spring.mail.*` 配置 |
| `TaskEmailNotificationService` | 业务邮件应用 Service |

两者都不应在 Controller 中拼 HTML 或直接处理 SMTP 细节。

```php

    return $mail->hasTo('publisher@example.test');

```

## 13. 手工验证

### 13.1 日志驱动

1. 保持 `MAIL_MAILER=log`。
2. 发布一个招标任务。
3. 使用另一名用户提交投标。
4. 查看 `storage/logs/laravel.log` 中的新投标邮件正文。
5. 发布者完成选标。
6. 再次检查日志中的 OWNER 和 COLLABORATOR 中标邮件。

### 13.2 SMTP 驱动

1. 配置公司提供的 SMTP 参数。
2. 执行 `php artisan config:clear`。
3. 使用测试邮箱完成投标和选标。
4. 确认邮件主题、金额、日期、角色和任务链接正确。
5. 确认每位中标成员只能看到自己的收件地址。

## 14. 常见错误

### 邮件没有真实发送

检查 `MAIL_MAILER`。值为 `log` 时只写日志，这是本地开发的预期行为。

### 日志显示人员没有可用邮箱

检查任务的 `created_by_snapshot.email`，以及人员列表接口中的 `eibEmail`。不要让前端临时填写邮箱绕过人员主数据。

### SMTP 认证失败

检查主机、端口、账号、密码、TLS/SSL 要求和发件地址权限，然后执行 `php artisan config:clear`。

### 邮件中的任务链接仍然指向 localhost

把 `.env` 的 `APP_URL` 修改为测试或生产环境真实地址，再执行 `php artisan config:clear`。

### 邮件失败但投标仍然成功

这是当前明确设计。通知失败会记录日志，不应回滚已经提交的核心业务。
