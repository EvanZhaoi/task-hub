## 3. 新增路由

受 SSO Session 中间件保护的任务路由现在包括：

| 请求 | 路径 | 作用 |
| --- | --- | --- |
| `GET` | `/tasks` | 查看任务大厅 |
| `POST` | `/tasks` | 发布任务 |
| `GET` | `/tasks/{task}` | 查看指定任务详情 |
| `POST` | `/tasks/{task}/bids` | 对指定任务提交投标 |

详情页和投标提交都必须先通过 `EnsureSsoAuthenticated`。未登录用户仍然会进入公司 SSO 登录流程。

## 4. 任务详情页

### 4.1 页面入口

任务大厅中的任务标题和“查看详情”文字都可以进入：

```text
/tasks/{taskId}
```

Laravel 根据路由中的 `{task}` 自动查询 `Task` Model，然后调用 `TaskController::show()`。

### 4.2 页面展示内容

任务详情页当前分为主内容区和右侧信息区。

主内容区展示：

- 任务状态、复杂度和分配方式。
- 任务标题、发布者和所属部门。
- 预算或最终金额。
- 期望交付日期、最终交付日期和招标截止时间。
- 当前有效投标数量。
- 经过后端白名单清洗的富文本任务描述。
- 任务附件名称和总部文件 ID。
- 当前用户有权查看的投标记录。

右侧信息区展示：

- 付款账号和付款部门快照。
- 发布时间和更新时间。
- `TaskEvent` 业务时间线。

### 4.3 详情数据组装

`TaskController::show()` 会一次性加载任务详情页需要的数据：

```text
Task
├── AttachmentRef（owner_type = TASK）
├── TaskEvent
├── ACTIVE Bid 数量
└── 当前用户可见的 Bid
    ├── BidMember
    └── AttachmentRef（owner_type = BID）
```

后端会把 BIGINT 主键转换为字符串，再通过 Inertia Props 传给 React，避免 JavaScript `number` 无法安全表示大整数。

任务描述在返回页面前会再次经过 `RichTextSanitizer`，用于兼容可能存在的历史数据。前端统一通过 `RichTextViewer` 展示，不直接拼接未经处理的 HTML。

### 4.4 投标可见范围

任务发布者可以查看该任务的全部投标记录。

普通用户只能查看自己作为成员参与的投标，不会收到其他投标人的报价和方案。

当前查询规则放在后端，不能依赖前端隐藏内容来实现数据隔离。

### 4.5 业务时间线

详情页会读取 `task_event` 并按时间倒序展示。页面已经准备了任务创建、发布、投标、选标、交付、变更、完成、取消和流标等事件文案。

当前实际新增写入的是 `BID_SUBMITTED`。`TaskEvent` 只作为时间线和审计记录，不用于反向重建 `Task.status`。

## 5. 投标入口

### 5.1 用户操作方式

满足投标条件时，详情页右上角显示“我要投标”按钮。点击后打开投标模态框，不跳转到单独页面。

表单包括：

- 投标金额。
- 承诺交付日期。
- 投标说明。
- 投标附件。

附件继续复用现有 `TaskAttachmentUploader`：文件先上传到总部文件服务，成功后表单只保留总部返回的文件 `id` 和 `name`。

提交成功后：

- 模态框关闭。
- 表单和本地附件状态清空。
- 页面重新获取最新详情数据。
- 页面显示“投标已提交。”成功提示。

### 5.2 前端按钮显示条件

后端通过 `canPlaceBid` 告诉前端当前用户是否允许显示可用的投标按钮。

只有同时满足以下条件时才返回 `true`：

1. 任务数据库状态为 `OPEN`。
2. 当前用户不是任务发布者。
3. `bidding_deadline` 存在并且仍在未来。
4. 当前用户没有以 `OWNER` 身份提交过其他 `ACTIVE` 投标。

不满足条件时页面显示禁用的“暂不可投标”按钮。

这个值只用于改善页面体验。真正影响数据合法性的规则仍然由后端 `PlaceBidService` 再次校验，用户无法通过绕过前端直接提交非法投标。

### 5.3 后端表单校验

`StoreBidRequest` 当前校验：

- 投标金额必填，必须是数字，范围兼容数据库 `DECIMAL(18,2)`。
- 承诺交付日期必填，不能早于当天。
- 投标说明可选，最多 5000 个字符。
- 附件最多 20 个。
- 每个附件必须包含有效的 `id` 和 `name`。
- 附件按 ID 去重，防止同一总部文件重复写入。

所有用户可见的字段错误和保存提示均使用中文。

## 6. 投标事务

`BidController` 只处理 HTTP 层工作：接收已经校验的请求、读取当前 SSO 用户、调用 `PlaceBidService`、返回重定向。

完整投标流程由 `PlaceBidService::execute()` 在一个数据库事务内完成：

```text
用户提交投标
    ↓
锁定 Task 记录
    ↓
校验任务为 OPEN、未截止、操作者不是发布者
    ↓
校验当前 OWNER 不存在其他 ACTIVE 投标
    ↓
创建 Bid
    ↓
创建 OWNER BidMember
    ↓
保存 BID 类型 AttachmentRef
    ↓
写入 BID_SUBMITTED TaskEvent
    ↓
提交事务
```

其中任何一步失败，整个事务都会回滚，不会留下只有 `bid`、没有成员或事件的残缺数据。

### 6.1 Bid

新投标会保存：

- `task_id`
- `amount`
- `delivery_date`
- `proposal`
- `status = ACTIVE`
- `revision_no`
- `active_key`

`active_key` 的格式为：

```text
任务ID:OWNER工号
```

数据库中的唯一索引用于保证同一任务、同一 OWNER 最多只有一条 `ACTIVE` 投标。

### 6.2 BidMember

当前第一版只开放单人投标，但仍然按照统一成员模型写入一条：

```text
role = OWNER
user_id = 当前登录人员工号
```

没有重新增加 `bid.bidder_id`，主投标人继续以 `bid_member.role = OWNER` 表示。

### 6.3 revision_no

创建 Bid 前会通过历史 `BidMember OWNER` 查询该用户在当前任务上的最大 `revision_no`，新记录使用最大值加一。

这为后续“撤回后重新投标并保留历史”提供了数据基础。当前撤回入口尚未实现。

### 6.4 投标附件

投标附件写入现有 `attachment_ref`：

- `owner_type = BID`
- `owner_id = bid.id`
- `attachment_id = 总部文件 ID`
- `attachment_name = 文件名称`
- `uploaded_by = 当前人员工号`

TaskHub 不保存真实文件内容。

### 6.5 投标事件

投标成功会新增 `BID_SUBMITTED` 事件，并在 `event_data` 中保存：

- 投标金额。
- 承诺交付日期。
- 投标修订号。
- 附件数量。

事件关联类型为 `BID`，关联 ID 为本次创建的 Bid ID。

## 7. 任务大厅三块式布局

最近一次提交只调整任务列表的前端布局，没有修改 Controller、Inertia Props 或数据库。

桌面端每张任务卡片分为三块：

```text
┌──────────────────────────────┬──────────────────┬────────────────┐
│ 左侧：任务信息               │ 中间：时间与人员 │ 右侧：预算投标 │
│ 标题 / 状态 / 等级           │ 发布者           │ 任务预算       │
│ 两行描述摘要                 │ 所属部门         │ 金额           │
│ 预计交付日期                 │ 截止时间/剩余天数│ X 人投标       │
└──────────────────────────────┴──────────────────┴────────────────┘
```

移动端和较窄屏幕会自动改成纵向排列，并用浅色分隔线区分三个区域。

### 7.1 左侧任务信息

左侧展示：

- 可点击进入详情页的任务标题。
- 当前展示状态。
- 三级等级徽标。
- 最多两行的富文本描述摘要，超出部分省略。
- 最终交付日期；没有最终交付日期时回退到期望交付日期。

当前数据库没有独立的“紧急程度”字段，页面暂时沿用现有 `complexity` 的 `LOW / MEDIUM / HIGH` 三级值显示为低、中、高。本次没有修改数据库字段或筛选逻辑。

### 7.2 中间时间与发布者

中间区域展示：

- 发布者姓名。
- 发布者所属部门。
- 招标截止时间。
- 根据截止时间计算的提示，例如“剩余 3 天”“1 天内截止”或“已截止”。

剩余时间只用于前端展示，是否允许投标仍以后端时间校验为准。

### 7.3 右侧预算与投标情况

右侧区域展示：

- “任务预算”标签。
- 突出的格式化金额。
- 当前 `ACTIVE` 投标数量。
- 任务详情入口。

原来卡片中的四项信息网格和独立底部按钮区域已经移除，避免预算、投标数、交付日期等信息重复出现。
