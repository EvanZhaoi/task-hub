# 29 与我相关的任务

## 1. 本章目标

在不新建重复页面的前提下，让用户从任务大厅快速找到：

- 自己发布的任务。
- 自己作为主投标人提交的任务。
- 自己作为投标协作成员或正式执行成员参与的任务。

本章只扩展列表查询和展示，不修改数据库结构，不改变投标和选标流程。

## 2. 最终效果

任务大厅顶部增加第一层范围切换：

```text
任务大厅 | 我发布的 | 我的投标 | 我参与的
```

第二层继续使用原有状态 Tab：

```text
全部 | 招标中 | 待选标 | 进行中 | 已完成 | 已流标 | 已取消
```

因此可以组合出“我发布的 + 待选标”、“我的投标 + 招标中”、“我参与的 + 进行中”等查询。

## 4. URL 和查询参数

范围使用 GET query string：

```text
/tasks                         任务大厅
/tasks?scope=PUBLISHED         我发布的
/tasks?scope=MY_BIDS           我的投标
/tasks?scope=PARTICIPATED      我参与的
```

使用 GET 的好处是页面可刷新、可收藏，浏览器前进后退可以恢复当前筛选。Laravel `withQueryString()` 会让分页链接保留 `scope` 和其他筛选参数。

## 5. 后端安全边界

Controller 只允许四种范围枚举：

```php
// 非法 scope 会回退为 HALL，不会直接进入 SQL。
private const SCOPES = ['HALL', 'PUBLISHED', 'MY_BIDS', 'PARTICIPATED'];
```

当前人员工号只能来自：

```php
// 不读取 request 中的 employeeNo，防止查询其他人的个人任务。
$employeeNo = $currentUser->employeeNo();
```

即使用户手工访问：

```text
/tasks?scope=PUBLISHED&employeeNo=OTHER_USER
```

后端仍然只查询当前 Session 人员的数据。

## 6. 四种范围的数据规则

### 6.1 任务大厅

不增加个人条件，保留原有公开任务查询。卡片不显示个人关系标签。

### 6.2 我发布的

```php
// created_by 保存任务发布者工号。
$query->where('created_by', $employeeNo);
```

卡片显示“我发布的”关系标签。

### 6.3 我的投标

只匹配 `bid_member.role = OWNER`：

```text
Task
  -> Bid
    -> BidMember(user_id = 当前工号, role = OWNER)
```

协作成员不进入“我的投标”，而是进入“我参与的”。卡片显示本人最新投标的状态、报价和 `revision_no`。

### 6.4 我参与的

查询满足任一条件的 Task：

```text
当前工号是某份 Bid 的 COLLABORATOR
OR
当前工号存在于 task_assignee
```

查询主体仍是 Task，所以同一人先协作投标、中标后又成为 TaskAssignee 时，不会出现两张重复任务卡片。

关系标签优先展示当前正式执行身份：

```text
TaskAssignee OWNER          -> 任务负责人
TaskAssignee COLLABORATOR   -> 执行协作者
仅 BidMember COLLABORATOR -> 协作投标
```

## 7. 前端结构

`Tasks/Index.tsx` 仍然是唯一列表页：

```text
Tasks/Index.tsx
  ├─ 范围 Tab
  ├─ 关键词 / 复杂度筛选
  ├─ 状态 Tab
  ├─ 任务卡片
  └─ 分页
```

范围、状态、复杂度和关键词都由 `filterUrl()` 统一组装 URL。点击“重置”只清除当前范围内的筛选，不会意外跳回任务大厅。

## 8. 为什么不新建 Service

这项功能只是一个列表读取：

- 没有数据库事务。
- 没有状态变更。
- 没有外部接口结果再加工。
- 查询和页面筛选强相关。

因此查询组装保留在 `TaskController@index` 的 private 方法中更容易阅读。如果未来 Dashboard、导出等多个入口真正复用同一套查询，再考虑抽取专用 Query 对象。

## 9. 验证内容

Feature Test 覆盖：

1. 伪造 `employeeNo` 无法查看他人发布的任务。
2. “我的投标”只返回 OWNER 记录。
3. 投标摘要包含状态、报价和版本。
4. “我参与的”同时包含协作投标和执行成员。
5. 同一任务同时命中两种参与关系时不重复。
6. 范围可以和状态筛选组合。
7. 未知 scope 安全回退到任务大厅。

## 10. 与 Spring Boot 的概念对照

| Laravel | Spring Boot 类似概念 | 说明 |
| --- | --- | --- |
| Query String | `@RequestParam` | 用于接收 scope 和筛选条件 |
| Eloquent `whereHas` | JPA Criteria / `exists` 子查询 | 按关联数据筛选 Task |
| Eloquent `with` | EntityGraph / fetch join | 预加载卡片需要的关系，避免 N+1 |
| Inertia Props | Controller 传递的 ViewModel | 后端把页面数据交给 React |
| `withQueryString()` | 分页参数传递 | 让下一页保留筛选条件 |

## 11. 本章总结

“与我相关的任务”已经在现有任务大厅内完成，没有复制页面，也没有引入全局状态管理。所有个人范围都以后端 Session 工号为准，前端只负责选择范围和展示结果。
