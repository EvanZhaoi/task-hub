# 15-基础 UI 与日期组件修正

## 本章目标

本章记录一次基础体验修正，不开发新的任务业务功能。

修正目标：

1. Button 鼠标样式统一放到 shadcn 基础组件中。
2. 发布任务弹窗字段布局更稳定，不被长文本撑破。
3. 发布任务表单不再直接使用原生 `date` / `datetime-local` 输入框。
4. 新增通用 `DatePicker` 和 `DateTimePicker`，后续业务表单统一复用。
5. 修正文档和代码中的错误 `Card as="..."` 示例。
6. 明确流标定时任务未来使用 Laravel Scheduler，不为每个任务创建独立 Cron。
7. 删除任务大厅重复的状态下拉框，状态只保留 Tab 筛选。
8. 付款账号改为可搜索选择器，支持按账号名称和 code 模糊匹配。

## 每一步操作

### 1. 统一 Button 鼠标样式

修改：

```text
resources/js/components/ui/button.tsx
```

关键代码：

```tsx
const buttonVariants = cva(
    // cursor-pointer 放在 Button 基础组件中，业务页面不需要为每个按钮重复写。
    // disabled 时使用 cursor-not-allowed，用户能明确知道按钮当前不可操作。
    'inline-flex h-10 cursor-pointer items-center justify-center whitespace-nowrap rounded-md text-sm font-medium transition-colors outline-none disabled:cursor-not-allowed disabled:opacity-50',
);
```

为什么这样做：

- 鼠标样式属于所有按钮的通用体验。
- 放在基础组件里，后续业务页面不会重复写 `cursor-pointer`。
- 不能保留 `disabled:pointer-events-none`，否则浏览器可能无法在禁用按钮上显示 `cursor-not-allowed`。

### 2. 修正 Card 标准用法

修改：

```text
resources/js/components/ui/card.tsx
```

关键代码：

```tsx
export function Card({ className, ...props }: ComponentProps<'div'>) {
    // Card 只负责基础边框、圆角、背景；内边距交给 CardContent 或页面控制。
    // 保持标准 shadcn 写法：Card 自身是 div；需要 article/section 语义时在外层包语义标签。
    return <div className={cn('rounded-lg border border-[#e5e7eb] bg-white', className)} {...props} />;
}
```

为什么这样做：

- shadcn 的 `Card` 默认是 `div`。
- `Card as="article"` 不是标准 shadcn 写法，文档里继续这样写会误导。
- 如果需要 HTML 语义，可以写成：

```tsx
<article>
    <Card>
        {/* 任务内容 */}
    </Card>
</article>
```

### 4. 新增 Calendar 基础组件

新增：

```text
resources/js/components/ui/calendar.tsx
```

作用：

- 基于 `react-day-picker` 封装日历。
- 统一 TaskHub 的日历样式。
- 业务组件只传 `selected` 和 `onSelect`。

注意：

- `react-day-picker` v10 的 `classNames` 字段和旧示例不同。
- 当前代码使用 `month_caption`，不要写旧版的 `caption`。
- `Calendar` 通常放在发布任务表单中，因此日期按钮、上月按钮、下月按钮都必须显式设置 `type="button"`。
- 如果不设置 `type="button"`，HTML 表单中的按钮默认是 `submit`，点击日期可能会触发表单提交。

### 5. 新增 DatePicker

新增：

```text
resources/js/components/common/DatePicker.tsx
```

作用：

- 替代业务页面中的原生日期输入。
- 统一提交 `YYYY-MM-DD`。
- 只负责一个自然日，不处理小时和分钟。

为什么放在 `components/common`：

- 它不是 shadcn 基础组件。
- 它是 TaskHub 业务页面会反复使用的组合组件。
- 后续任务交期、变更交期、交付日期都可以复用。

### 6. 新增 DateTimePicker

新增：

```text
resources/js/components/common/DateTimePicker.tsx
```

作用：

- 用于需要具体时间点的字段，例如招标截止时间。
- 日期部分复用 `DatePicker`。
- 小时支持 `0-23`。
- 分钟支持 `0-59`。
- 不限制为 5 分钟或 15 分钟步长。

提交格式：

```text
YYYY-MM-DDTHH:mm
```

这个格式和原来的 `datetime-local` 一致，所以后端 `StoreTaskRequest` 不需要改。

### 7. 修正发布任务弹窗布局

修改：

```text
resources/js/Pages/Tasks/Index.tsx
```

布局规则：

```text
任务标题：100%
任务描述：100%
预算金额 / 复杂度：50% / 50%
期望交付日期 / 招标截止时间：50% / 50%
付款账号：100%

```

关键代码：

```tsx
<div className="grid grid-cols-1 gap-4 sm:grid-cols-2">
    <Field label="预算金额" message={form.errors.budget} required>
        <Input className="w-full" />
    </Field>

    <Field label="复杂度" message={form.errors.complexity} required>
        <NativeSelect className="w-full min-w-0" />
    </Field>
</div>
```

`Field` 容器：

```tsx
function Field({ children, label, message, required = false }: FieldProps) {
    return (
        <label className="block min-w-0 space-y-1.5">
            {/* 字段标题、控件、错误提示 */}
        </label>
    );
}
```

为什么加 `min-w-0`：

- CSS Grid / Flex 子项默认最小宽度可能由内容撑开。
- 付款账号名称很长时，如果父容器没有 `min-w-0`，Dialog 会被撑破。
- `min-w-0` 允许子项在可用宽度内收缩。

### 8. 修正付款账号搜索选择器

修改：

```text
resources/js/components/common/PaymentAccountCombobox.tsx
resources/js/Pages/Tasks/Index.tsx
```

关键代码：

```tsx
<Field label="付款账号" message={form.errors.paymentAccountId} required>
    <PaymentAccountCombobox
        // 付款账号数量可能比较多，普通 Select 不适合快速查找。
        // 这里改成可输入搜索的 Combobox，但提交值仍然是 paymentAccountId。
        disabled={paymentAccountOptions.length === 0}
        name="paymentAccountId"
        onChange={(value) => form.setData('paymentAccountId', value)}
        options={paymentAccountOptions}
        value={form.data.paymentAccountId}
    />
</Field>
```

为什么这样做：

- 付款账号来自外部接口，数量可能明显多于复杂度这种固定枚举。
- 普通 Select 只能滚动查找，账号多时效率低。
- Combobox 允许用户输入账号名称或账号 code，实时缩小候选范围。
- 选择后仍然只提交账号 ID，不改变后端字段和数据库结构。
- 长账号名称在按钮和列表里都使用 `truncate`，不会撑破 Dialog。

`NativeSelect` 自身应保持下面这种基础样式：

```tsx
export function NativeSelect({ className, ...props }: ComponentProps<'select'>) {
    // 这里只封装原生 select 的基础视觉和 focus 样式。
    // 宽度、截断、Grid 收缩能力由具体业务场景传 className 决定。
    return (
        <select
            className={cn(
                'h-10 rounded-md border border-[#d1d5db] bg-white px-3 text-sm text-[#374151] outline-none transition-colors',
                'focus:border-[#5e6ad2] focus:ring-2 focus:ring-[#5e6ad2]/15',
                className,
            )}
            {...props}
        />
    );
}
```

这条规则很重要：

- `Button` 的鼠标样式是所有按钮都需要的交互反馈，可以放在基础组件中。
- `NativeSelect` 的 `w-full` / `truncate` 是某个布局场景需要的尺寸规则，不应该全局默认。
- 发布任务弹窗修布局时，不能顺手改变任务大厅筛选区、任务卡片、分页等已有布局。

### 9. 修正 DatePicker / DateTimePicker 交互

修改：

```text
resources/js/components/ui/calendar.tsx
resources/js/components/common/DatePicker.tsx
resources/js/components/common/DateTimePicker.tsx
```

日历按钮关键代码：

```tsx
DayButton: ({ day: _day, modifiers: _modifiers, ...buttonProps }: DayButtonProps) => (
    // 日历经常放在 form 里；button 默认 type 是 submit。
    // 如果不显式写 type="button"，点击日期可能会提交发布任务表单。
    <button {...buttonProps} type="button" />
),
```

时间输入关键代码：

```tsx
<div className="grid w-full min-w-0 grid-cols-[minmax(0,1fr)_4.25rem_4.25rem] items-center gap-2 sm:grid-cols-[minmax(0,1fr)_5rem_5rem]">
    <DatePicker disabled={disabled} onChange={updateDate} placeholder="请选择日期" value={date} />

    <Input
        // 输入过程中不立即补 0，让用户可以自然输入 2 或 23。
        // 离开输入框时再规整到 00-23。
        aria-label="小时"
        className="px-2 text-center tabular-nums"
        disabled={disabled}
        inputMode="numeric"
        maxLength={2}
        onBlur={(event) => commitHour(event.target.value)}
        onChange={(event) => updateHour(event.target.value)}
        placeholder="时"
        type="text"
        value={hourInput}
    />

    <Input
        // 分钟支持任意 00-59，不限制 5 分钟或 15 分钟间隔。
        aria-label="分钟"
        className="px-2 text-center tabular-nums"
        disabled={disabled}
        inputMode="numeric"
        maxLength={2}
        onBlur={(event) => commitMinute(event.target.value)}
        onChange={(event) => updateMinute(event.target.value)}
        placeholder="分"
        type="text"
        value={minuteInput}
    />
</div>
```

为什么这样做：

- 发布任务弹窗中，招标截止时间位于两列 Grid 的右侧，横向空间比整行输入框更窄。
- 原来的小时输入框左侧放了时钟图标，并且有 `pl-7`，数字可用空间不足。
- 现在去掉图标、给小时和分钟列设置更明确的宽度，`23` / `59` 都能完整显示。
- 时间输入改成受控文本输入：输入时只限制数字位数，失焦时再统一补 0 和限制范围。
- `tabular-nums` 让数字等宽显示，输入变化时视觉更稳定。

### 10. 修正任务大厅筛选区

修改：

```text
resources/js/Pages/Tasks/Index.tsx
app/Http/Controllers/TaskController.php
```

关键代码：

```tsx
<form action="/tasks" className="flex flex-col gap-3 lg:flex-row lg:items-center" method="GET">
    {/* 状态由下方 Tab 控制；提交搜索或复杂度筛选时用 hidden 保留当前状态。 */}
    {filters.status !== 'ALL' ? <input name="status" type="hidden" value={filters.status} /> : null}

    <div className="relative min-w-0 flex-1">
        <span className="pointer-events-none absolute left-3 top-1/2 -translate-y-1/2 text-sm text-[#9ca3af]">
            搜索
        </span>
        <Input className="pl-12" defaultValue={filters.keyword} name="keyword" placeholder="输入标题或描述关键词" />
    </div>

    <div className="relative min-w-0 lg:w-44">
        <span className="pointer-events-none absolute left-3 top-1/2 -translate-y-1/2 text-sm text-[#9ca3af]">
            复杂度：
        </span>
        <NativeSelect className="w-full pl-[4.5rem]" defaultValue={filters.complexity} name="complexity">
            {complexityOptions.map((option) => (
                <option key={option.value} value={option.value}>
                    {option.label}
                </option>
            ))}
        </NativeSelect>
    </div>
</form>
```

为什么这样做：

- 页面已经有状态 Tab，再放一个状态下拉会让用户不知道两个筛选谁优先。
- 状态 Tab 更适合任务大厅的主筛选；复杂度是辅助筛选，保留在表单里。
- 隐藏字段用于保留当前 Tab 状态，避免用户在“待选标”下搜索后跳回“全部”。
- 复杂度前缀固定放在控件前方，选项只显示 `全部 / 低 / 中等 / 高`，避免出现 `复杂度：全部` 这种重复文字。

### 11. 补充流标定时任务规范

第 13 章保留原来的定时任务条目，不新增重复条目。

补充规则：

```text
Laravel Scheduler 每分钟执行一次
↓
扫描 OPEN && bidding_deadline <= now() 的任务
↓
调用 ExpireOpenTasksService
↓
Service 内部再次锁定 Task 并校验没有 ACTIVE Bid
↓
符合条件才改为 FAILED 并写 TASK_FAILED
```

关键要求：

- 不为每个任务单独创建 Cron。
- Scheduler 只负责定时触发。
- `ExpireOpenTasksService` 负责业务判断和事务。
- 处理逻辑必须幂等。
- 已经不是 `OPEN` 的任务不能重复处理。
- 已经有 `ACTIVE` 投标的截止任务不能自动流标，只能派生显示“待选标”。

## 常见错误

| 错误 | 原因 | 处理 |
|---|---|---|
| `caption does not exist in type ClassNames` | `react-day-picker` v10 不再使用旧版 `caption` className | 使用 `month_caption` |
| Dialog 被长账号名称撑宽 | 发布弹窗里的字段容器或付款账号 Select 没有 `min-w-0` / `truncate` | 检查 `Field` 和发布弹窗中的 `NativeSelect className` |
| 任务大厅筛选区宽度被改变 | 把弹窗需要的 `w-full` / `truncate` 写进了 `NativeSelect` 默认样式 | 恢复 `NativeSelect` 基础样式，把布局 class 放回发布弹窗 |
| 时间输入数字显示不全 | DateTimePicker 小时/分钟列太窄，或图标占用了输入框空间 | 去掉小时输入图标，给小时/分钟输入设置合适列宽和 `px-2` |
| 日期点击后表单被提交 | Calendar 内部按钮没有设置 `type="button"` | 在 `Calendar` 自定义 DayButton / 月份切换按钮 |
| 付款账号太多不好找 | 使用普通 Select 无法搜索 | 使用 `PaymentAccountCombobox` |
| 日期提交后后端校验失败 | 提交格式不是 `YYYY-MM-DD` 或 `YYYY-MM-DDTHH:mm` | 检查 `DatePicker` / `DateTimePicker` 的 `onChange` |
| disabled 按钮不显示禁用光标 | Button 中仍有 `disabled:pointer-events-none` | 移除该 class，保留 `disabled:cursor-not-allowed` |
| `Card as` 报 TypeScript 错误 | 标准 Card 不支持 `as` 属性 | 用外层 `article` / `section` 包住 `Card` |

## 本章总结

本次修正只处理基础 UI 和文档一致性，没有新增业务功能。

关键原则：

- 通用交互样式放到基础组件。
- 业务表单使用 common 组合组件，避免每个页面重复处理日期格式。
- shadcn 基础组件保持通用，不写 TaskHub 业务逻辑。
- 文档示例必须和真实代码保持一致。
- 定时任务使用 Laravel Scheduler 统一扫描，不为每个业务对象创建独立 Cron。
