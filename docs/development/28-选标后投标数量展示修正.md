# 28 选标后投标数量展示修正

## 本章目标

修正“任务已经选标，但列表显示 0 人投标、详情显示有效投标 0 个”的展示问题。

本次不修改选标业务状态，也不修改数据库。核心是区分两种统计口径：

- `activeBidCount`：当前状态为 `ACTIVE` 的投标数，用于待选标判断和业务校验。
- `bidCount`：任务的历史累计投标数，包含选标后的 `ACCEPTED` 和 `LOST` 记录。

## 问题根因

选标事务会按业务规则更新 Bid：

```text
中标投标：ACTIVE -> ACCEPTED
其他投标：ACTIVE -> LOST
```

因此，选标结束后 `ACTIVE` 数量必然是 0。这只表示“没有继续等待选择的投标”，不表示“从来没有人投标”。

修正前，列表和详情摘要都把 `activeBidCount` 当成展示总数，所以产生误导。

## 涉及文件

- `app/Http/Controllers/TaskController.php`
- `resources/js/types/task.ts`
- `resources/js/Pages/Tasks/Index.tsx`
- `resources/js/Pages/Tasks/Show.tsx`
- `tests/Feature/ApplicationShellTest.php`

## 后端调整

任务列表查询同时统计当前有效数和历史累计数：

```php
->withCount([
    // 仅统计当前仍可参与选标的方案。
    'bids as active_bid_count' => fn (Builder $query): Builder => $query->where('status', 'ACTIVE'),
    // 统计全部历史投标，选标后不会归零。
    'bids as bid_count',
]);
```

`active_bid_count` 仍然保留，因为“已截止且存在 ACTIVE 投标”是派生状态“待选标”的判断条件。不能为了修正文字展示而用总数替换它。

## 前端展示规则

### 任务列表

- 招标任务统一显示“共 X 份投标”。
- 直接指派任务显示“直接指派”，不显示“0 份投标”。
- 使用“份”而不是“人”，因为一份联合投标可以包含多名成员。

### 任务详情

- `OPEN` 招标任务显示“有效投标 X 个”，用户关心的是当前还有多少可选方案。
- `ASSIGNED` 等选标后状态显示“累计投标 X 份”。
- `DIRECT` 任务显示“分配方式：直接指派”。

投标详情的权限规则没有改变：无权用户只能看到数量提示，不能看到他人的报价、成员、说明和附件。

## 验证场景

```text
1. 任务初始有 2 份 ACTIVE 投标。
2. 发布者选中其中 1 份。
3. 中标 Bid 变为 ACCEPTED，另一份变为 LOST。
4. activeBidCount = 0。
5. bidCount / bidOverview.totalCount = 2。
6. 列表显示“共 2 份投标”。
7. 详情摘要显示“累计投标 2 份”。
```

## 本章总结

投标记录没有丢失，问题是展示层使用了错误的统计口径。修正后，业务层仍可以使用 ACTIVE 数判断待选标，用户界面则能完整表达历史投标事实。
