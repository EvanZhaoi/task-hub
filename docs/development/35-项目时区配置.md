# 35 - 项目时区配置

## 1. 本章目标

本章将 TaskHub 的业务时区统一为中国标准时间，并解释 Laravel、PHP、MySQL `TIMESTAMP` 和前端日期之间的关系。

统一后的配置是：

```text
Laravel / PHP：Asia/Shanghai
MySQL 连接会话：+08:00
浏览器页面：使用后端返回的本地业务时间
Token ISO 时间：继续使用 UTC Z 格式表示绝对时间
```

## 2. 涉及文件

- `.env.example`：提供新环境的默认时区变量。
- `.env`：本机运行环境使用相同配置，但该文件不提交真实密钥。
- `config/app.php`：Laravel 应用时区读取 `APP_TIMEZONE`。
- `config/database.php`：MySQL 连接会话时区读取 `DB_TIMEZONE`。
- `tests/Feature/TimezoneConfigurationTest.php`：防止后续升级框架时恢复为 UTC。

## 3. 环境变量

在 `.env` 中配置：

```env
# Laravel、Carbon、now()、日志业务时间和 Scheduler 使用该时区。
APP_TIMEZONE=Asia/Shanghai

# MySQL 当前连接对 TIMESTAMP 的读写使用东八区。
DB_TIMEZONE=+08:00
```

为什么两个值写法不同：

- PHP 支持 `Asia/Shanghai` 这种 IANA 时区名称，能够表达地区时区规则。
- MySQL 只有导入时区表后才能识别地区名称；`+08:00` 不依赖额外数据库配置，更适合当前部署环境。

## 4. Laravel 配置

`config/app.php`：

```php
// 不在代码中写死部署值；环境未配置时仍默认使用中国标准时间。
'timezone' => env('APP_TIMEZONE', 'Asia/Shanghai'),
```

这会影响：

- `now()` 和 Carbon 默认时区。
- Eloquent 日期字段格式化。
- 招标截止时间判断。
- Laravel Scheduler 的执行时区。
- 邮件和 Inertia Props 中格式化后的业务时间。

## 5. MySQL 连接时区

`config/database.php` 的 MySQL 连接增加：

```php
// PDO 建立连接时会设置 MySQL Session time_zone。
'timezone' => env('DB_TIMEZONE', '+08:00'),
```

MySQL `TIMESTAMP` 内部以 UTC 保存，并根据当前数据库连接时区进行写入和读取转换。明确连接时区后，即使 MySQL 服务器部署在 UTC 系统中，TaskHub 读取到的业务时间也保持为东八区。

这不是修改数据库字段，也不会把 `TIMESTAMP` 改成 `DATETIME`。

## 6. 为什么 ISO 时间仍可能显示 Z

代码中的 `toISOString()` 会生成类似：

```text
2026-11-11T05:00:00.000000Z
```

结尾 `Z` 表示 UTC 绝对时间，常用于 SSO Token 到期时间和 JSON 事件快照。它与下面的中国标准时间表示的是同一时刻：

```text
UTC：          2026-11-11 05:00:00
Asia/Shanghai：2026-11-11 13:00:00
```

因此不要把所有 `toISOString()` 强行改成本地时间字符串。页面展示使用后端的 `format('Y-m-d H:i')`，绝对时间交换继续使用 ISO 格式。

## 7. 让配置生效

修改 `.env` 后，在项目根目录执行：

```bash
# 清除旧配置缓存，否则运行中的 Laravel 可能继续使用 UTC。
php artisan config:clear

# 如果开发服务正在运行，停止后重新启动。
composer run dev
```

生产环境如果执行过 `php artisan config:cache`，应在发布时重新生成配置缓存并重启 PHP-FPM。

## 8. 验证步骤

在项目根目录执行：

```bash
# 查看 Laravel 当前配置和 now() 的偏移。
php artisan tinker --execute="dump(config('app.timezone')); dump(config('database.connections.mysql.timezone')); dump(now()->format('Y-m-d H:i:s P'));"
```

预期包含：

```text
Asia/Shanghai
+08:00
日期时间 +08:00
```

然后运行：

```bash
php artisan test
```

页面验证：

1. 新建任务时填写的招标截止时间保存后不应相差 8 小时。
2. 任务大厅、详情和邮件中的截止时间应一致。
3. 定时任务应在页面显示的截止时间之后处理任务。

## 9. 常见错误

### 修改 `.env` 后仍显示 UTC

执行：

```bash
php artisan config:clear
```

并重启开发服务或 PHP-FPM。

### MySQL 报 Unknown or incorrect time zone

确认使用：

```env
DB_TIMEZONE=+08:00
```

不要在当前环境中改成 `Asia/Shanghai`，除非已经确认 MySQL 时区表可用。

### 前端倒计时仍不正确

检查后端是否返回 `YYYY-MM-DD HH:mm` 本地业务时间，以及浏览器电脑的系统时区是否正确。TaskHub 当前日期选择器提交的是本地时间，不附带 UTC `Z`。

## 10. 本章总结

TaskHub 现在明确使用 `Asia/Shanghai` 作为 Laravel 业务时区，并将 MySQL 连接时区固定为 `+08:00`。业务日期、数据库 `TIMESTAMP`、定时任务和页面展示使用同一时间基准，同时保留 Token 等跨系统绝对时间的标准 UTC ISO 表示。
