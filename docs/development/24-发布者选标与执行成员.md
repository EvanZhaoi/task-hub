# 24 - 发布者选标与执行成员

## 1. 本章目标

本章完成招标流程中最关键的闭环：任务发布者从有效投标中选定一个方案，并把该投标的全部成员固化为任务执行成员。

完成后的业务流程为：

```text
发布招标任务
    ↓
单人或多人联合投标
    ↓
发布者查看投标记录
    ↓
确认选择某个 ACTIVE 投标
    ↓
Task 进入 ASSIGNED
    ↓
BidMember 复制为 TaskAssignee
    ↓
详情页展示负责人和协作成员
```

## 2. 学习目标

完成本章后，应能理解：

1. 为什么完整业务动作应放在 `SelectBidService`，而不是 Controller。
2. 为什么选标必须使用数据库事务和行锁。
3. 为什么金额、交期和成员不能由浏览器重新提交。
4. `BidMember` 和 `TaskAssignee` 的职责区别。
5. Laravel ValidationException 如何通过 Inertia 显示中文业务错误。
6. React 确认弹窗如何只提交业务对象 ID。

## 3. 前置条件

开始前应确认：

- `task`、`bid`、`bid_member`、`task_assignee`、`task_event` 已按 `database/schema.sql` 创建。
- 任务详情和投标功能已经完成。
- 当前用户通过 `CurrentUserService` 获取，不从请求参数读取工号。
- 至少存在一个 `status = OPEN`、`assignment_type = BIDDING` 的任务和一个有效投标。

本章不修改数据库结构。

## 5. 生成请求类和 Service

命令执行目录：项目根目录。

```bash
# FormRequest 负责 HTTP 请求形态；实际业务权限在事务内检查。
php artisan make:request SelectBidRequest

# Service 表达“选择一个投标”这一完整业务动作。
php artisan make:class Services/SelectBidService
```

命令会生成：

```text
app/Http/Requests/SelectBidRequest.php
app/Services/SelectBidService.php
```

这里不使用宽泛的 `BidService`。`SelectBidService` 的名称直接说明它只负责选标，打开文件即可看到完整流程。

## 6. 定义选标请求

`SelectBidRequest` 的规则为空不是遗漏，而是安全设计：

```php
<?php

namespace App\Http\Requests;

use Illuminate\Contracts\Validation\ValidationRule;
use Illuminate\Foundation\Http\FormRequest;

class SelectBidRequest extends FormRequest
{
    /**
     * 登录校验由 SSO Middleware 完成，业务权限由 Service 在事务内检查。
     */
    public function authorize(): bool
    {
        return true;
    }

    /**
     * 选标只使用 URL 中的 Task 和 Bid，不接收金额、交期和成员等可篡改字段。
     *
     * @return array<string, ValidationRule|array<mixed>|string>
     */
    public function rules(): array
    {
        return [];
    }
}
```

前端只需要发送：

```text
POST /tasks/{task}/bids/{bid}/accept
```

最终金额、最终交期和执行成员必须从锁定后的数据库记录读取。否则用户可以在浏览器中篡改金额或成员后再提交。

## 7. 实现选标事务

`SelectBidService::execute()` 的执行顺序为：

```text
开始事务
    ↓
锁定 Task
    ↓
校验发布者、分配方式和任务状态
    ↓
锁定目标 Bid
    ↓
校验 Bid 归属和状态
    ↓
读取并锁定 BidMember
    ↓
确认恰好一个 OWNER
    ↓
目标 Bid -> ACCEPTED
    ↓
其他 ACTIVE Bid -> LOST
    ↓
Task -> ASSIGNED，version + 1
    ↓
复制 BidMember -> TaskAssignee
    ↓
写 BID_ACCEPTED 和 TASK_ASSIGNED
    ↓
提交事务
```

核心入口完整代码如下：

```php
/**
 * 执行完整选标事务。
 */
public function execute(Task $task, Bid $bid, SsoUser $user): Task
{
    return DB::transaction(function () use ($bid, $task, $user): Task {
        // 锁定任务，避免两个请求同时选中不同投标。
        $lockedTask = Task::query()
            ->whereKey($task->id)
            ->lockForUpdate()
            ->firstOrFail();

        $this->assertTaskCanSelectBid($lockedTask, $user->employeeNo());

        // 路由绑定对象可能已经过期，所以必须在锁内重新查询和校验 Bid。
        $lockedBid = Bid::query()
            ->whereKey($bid->id)
            ->lockForUpdate()
            ->firstOrFail();

        $this->assertBidCanBeSelected($lockedTask, $lockedBid);

        // 锁定投标成员，防止选标过程中成员集合发生变化。
        $members = BidMember::query()
            ->where('bid_id', $lockedBid->id)
            ->orderByRaw("role = 'OWNER' DESC")
            ->orderBy('id')
            ->lockForUpdate()
            ->get();
        $owner = $members->where('role', 'OWNER');

        // 每个投标必须且只能有一个主投标人。
        if ($owner->count() !== 1) {
            throw ValidationException::withMessages([
                'bid' => '目标投标的主投标人数据不完整，暂时无法选标。',
            ]);
        }

        // 已有执行成员意味着任务已经被指派，禁止重复复制成员。
        if (TaskAssignee::query()->where('task_id', $lockedTask->id)->exists()) {
            throw ValidationException::withMessages([
                'bid' => '任务已经存在执行成员，不能重复选标。',
            ]);
        }

        $ownerEmployeeNo = (string) $owner->first()->user_id;

        // private 方法按业务顺序排列，打开 execute() 就能理解完整选标流程。
        $this->acceptTargetBid($lockedBid);
        $this->loseOtherActiveBids($lockedTask, $lockedBid);
        $this->assignTask($lockedTask, $lockedBid, $ownerEmployeeNo, $user->employeeNo());
        $this->copyMembersToAssignees($lockedTask, $members->all());
        $this->createSelectionEvents(
            $lockedTask,
            $lockedBid,
            $ownerEmployeeNo,
            $members->count(),
            $user->employeeNo(),
        );

        // 返回刷新后的任务，确保调用方读取到 ASSIGNED 和最新 version。
        return $lockedTask->refresh();
    });
}
```

这些 private 方法只服务于当前选标流程，所以保留在 `SelectBidService` 中。这样既能从 `execute()` 读懂主流程，也不会为了拆分而建立很多公共类。

### 7.1 为什么需要 `lockForUpdate()`

普通查询只能看到读取时的数据。如果发布者快速点击两次，或两个浏览器同时选标，两个请求都可能先读到 `OPEN`。

`lockForUpdate()` 会在事务中锁定目标行。第二个请求必须等待第一个事务结束，随后重新读取到 `ASSIGNED`，并被状态校验拒绝。

这类似 Spring 中在事务方法内使用悲观写锁，但 Laravel 直接通过 Query Builder 表达。

### 7.2 为什么复制成员

`bid_member` 表示某次投标方案的成员，是投标历史的一部分。`task_assignee` 表示正式执行成员，是后续交付权限和“我参与的任务”的依据。

选标后复制而不是实时关联，原因是：

- 投标记录需要永久保留历史。
- 正式执行关系不应依赖投标列表临时推导。
- DIRECT 模式没有 Bid，但仍然需要 TaskAssignee。

## 8. Controller 与路由

路由位于 SSO Middleware 保护组中：

```php
// 发布者选标会修改多张表，完整事务交给 SelectBidService。
Route::post(
    '/tasks/{task}/bids/{bid}/accept',
    [BidController::class, 'accept'],
)->name('tasks.bids.accept');
```

Controller 保持简短：

```php
/**
 * 选定指定投标为中标方案。
 */
public function accept(
    SelectBidRequest $request,
    Task $task,
    Bid $bid,
    CurrentUserService $currentUser,
    SelectBidService $selectBid,
): RedirectResponse {
    // 当前工号只能来自统一认证服务，不能接受前端传入的 employeeNo。
    $selectBid->execute($task, $bid, $currentUser->user());

    return redirect()
        ->route('tasks.show', $task)
        ->with('success', '已选定中标方案，任务进入进行中。');
}
```

Controller 不控制事务，也不直接更新 Model。这对应 Spring MVC 中 Controller 调用一个事务型应用 Service。

## 9. 前端确认弹窗

任务发布者会在每个 ACTIVE 投标卡片看到“选择该方案”。弹窗展示：

- 主投标人。
- 协作成员。
- 最终金额。
- 最终交期。

提交代码只使用 URL 参数：

```tsx
/**
 * 提交选标动作；金额、交期和成员不重新发送给后端。
 */
function selectBid(): void {
    form.post(`/tasks/${taskId}/bids/${bid.id}/accept`, {
        preserveScroll: true,
        // 成功返回新的详情 Props 后关闭确认弹窗。
        onSuccess: () => setOpen(false),
    });
}
```

后端返回的 `canSelect` 只用于控制按钮显示。Service 仍会再次校验，因为隐藏按钮不能代替后端权限控制。

## 10. 执行成员展示

任务详情直接读取 `task_assignee`：

```text
负责人：TaskAssignee.role = OWNER
协作成员：TaskAssignee.role = COLLABORATOR
```

人员目录可用时显示姓名和部门，接口不可用时回退到工号。这样外部人员接口异常不会阻止用户查看任务历史。

第一期执行成员只读，不支持执行期间新增、删除或更换。

## 11. 错误处理

Service 使用 `ValidationException::withMessages()` 返回中文业务错误，例如：

```php
throw ValidationException::withMessages([
    // bid 是页面统一展示选标业务错误的键。
    'bid' => '只有任务发布者可以选择中标方案。',
]);
```

Inertia 会把错误放入页面 `errors` Props。详情页显示错误提示，但数据库事务已经回滚，不会留下部分状态。

## 14. 常见错误

### 14.1 提示只有发布者可以选标

检查当前 Session 中的工号是否等于 `task.created_by`。不要通过前端参数临时覆盖工号。

### 14.2 提示目标投标已失效

检查 Bid 是否仍为 `ACTIVE`。`WITHDRAWN`、`ACCEPTED` 和 `LOST` 都不能再次选择。

### 14.3 提示主投标人数据不完整

检查该 Bid 的 `bid_member`：必须且只能有一条 `role = OWNER`。单人投标也必须写 OWNER。

### 14.4 出现重复执行成员

检查是否绕过 Service 手工写入 `task_assignee`。选标事务发现任务已有成员时会拒绝重复处理。

### 14.5 测试请求跳转到 `/login`

受保护路由的 Feature Test 必须同时准备用户 Session 和未过期 Token Session，才能通过 SSO Middleware。

## 15. Laravel 与 Spring Boot 对照

| Laravel | Spring Boot 中相近概念 | 说明 |
| --- | --- | --- |
| FormRequest | DTO + Bean Validation | 本章没有可编辑字段，业务权限在锁内校验 |
| Route Model Binding | `@PathVariable` 后查询 Entity | Laravel 自动把 `{task}` 转为 Task Model |
| Service `execute()` | `@Transactional` Service 方法 | 一个方法表达一个完整业务动作 |
| `DB::transaction()` | `@Transactional` | 异常时整体回滚 |
| `lockForUpdate()` | `PESSIMISTIC_WRITE` | 防止并发重复选标 |
| ValidationException | 业务校验异常 + BindingResult | Inertia 自动共享字段错误 |
| Inertia `useForm()` | 前端表单请求封装 | 保留 SPA 体验，但仍走 Laravel 路由 |

这些概念只是职责相近，不代表实现机制完全相同。Laravel 的事务在代码闭包中显式表达，Inertia 则同时连接服务端路由和 React 页面。

## 17. 本章总结

选标不是一次单表更新，而是一个需要原子完成的业务动作。`SelectBidService` 让任务、投标、成员和事件在同一事务中保持一致；确认弹窗负责防止误操作，但数据库锁和后端校验才是真正的数据保障。
