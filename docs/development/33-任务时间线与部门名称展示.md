# 33 - 任务时间线与部门名称展示

## 1. 本章目标

本章记录三项详情展示修正：时间线保存操作人姓名、同一秒事件稳定排序，以及前端长部门名称缩短显示。修改只补充历史展示信息，不改变人员权限判断和业务状态流转。

## 2. 涉及文件

- `database/schema.sql`：为新建数据库声明 `task_event.operator_name`。
- `database/patches/20261110_add_task_event_operator_name.sql`：为现有数据库补字段。
- `app/Models/TaskEvent.php`：允许 Eloquent 写入姓名快照。
- `app/Services/*TaskService.php`：业务事件写入操作人工号和姓名。
- `app/Http/Controllers/TaskController.php`：稳定排序事件并返回姓名。
- `resources/js/utils/personnel.ts`：集中处理部门名称简称。
- 任务列表、详情、人员选择器和顶部布局：只在展示时使用简称。

## 3. 更新现有数据库

在项目根目录执行：

```bash
# 将补丁应用到当前 .env 指向的 MySQL 数据库。
mysql -u 用户名 -p 数据库名 < database/patches/20261110_add_task_event_operator_name.sql
```

补丁等价于：

```sql
-- 姓名是事件发生时的展示快照；稳定身份仍以 operator_id 工号为准。
ALTER TABLE `task_event`
  ADD COLUMN `operator_name` VARCHAR(100) NULL COMMENT '操作人姓名快照；系统事件可为空'
  AFTER `operator_id`;
```

字段允许为空，因为自动流标、截止提醒等系统事件没有人员操作人。旧事件也不会自动补姓名，页面会回退显示已有工号。

## 4. 为什么同时保存工号和姓名

`operator_id` 是稳定工号，用于审计和人员匹配；`operator_name` 是事件发生时的姓名快照，用于时间线直接展示。两者职责不同，不能用姓名替代工号，也不需要在每次打开详情时为旧事件逐条调用人员接口。

新的人工事件写入示例：

```php
TaskEvent::query()->create([
    // 工号继续作为稳定人员标识。
    'operator_id' => $user->employeeNo(),
    // 姓名只作为事件发生时的历史展示快照。
    'operator_name' => $user->displayName(),
]);
```

详情页优先显示 `operatorName`，旧记录没有姓名时回退到 `operatorId`，因此上线补字段后不会让旧时间线变成空白。

## 5. 同一秒事件排序

MySQL `TIMESTAMP` 当前只记录到秒。创建任务和发布任务在同一个事务内连续执行，两个事件经常拥有相同的 `created_at`。只按时间排序时，数据库不承诺相同时间记录的先后顺序。

现在查询使用：

```php
$query
    // 最新事件优先，用户打开详情后先看到最近发生的变化。
    ->latest('created_at')
    // 时间相同时再按递减事件 ID 排序。
    ->orderByDesc('id');
```

事件 ID 由项目 ID 生成器按写入顺序递增。时间线倒序显示时，同一秒内会稳定显示后写入的 `TASK_PUBLISHED`，再显示先写入的 `TASK_CREATED`。

## 6. 部门名称缩短规则

外部人员接口可能返回完整组织路径。前端 `formatDepartmentName()` 只负责展示，不修改 Session、人员缓存或任务快照中的原始值。

规则是取第一个 `&` 之后、最后一个 `&` 之前的内容：

```text
公司&研发中心&开发一部&开发组
     ↓
研发中心&开发一部
```

如果名称没有至少两个 `&`，则保留原名称。例如 `开发一部` 和 `公司&开发一部` 都不会被错误截空。人员搜索仍使用完整部门名称，只有界面文字使用简称。

## 7. 验证步骤

在项目根目录执行：

```bash

npm run typecheck
npm run build

# 验证事件写入、时间线顺序和现有业务流程。

```

页面检查：

1. 新发布一个任务，时间线顶部依次显示“发布任务”和“创建任务”。
2. 两条记录显示当前操作人姓名，不再只显示工号。
3. 查看任务大厅、任务详情、顶部用户区域和人员选择器，长部门路径显示为简称。
4. 查看旧事件；没有姓名快照时仍显示工号。

## 8. 注意事项

- 部署现有环境时必须先执行数据库补丁，再发布包含 `operator_name` 写入的 PHP 代码。
- 不要删除 `operator_id`；姓名不是稳定的权限和审计标识。
- 不在前端截断并覆盖原始数据，避免搜索和后续业务失去完整部门路径。
- 系统自动事件的 `operator_name` 保持 `NULL`，页面无需伪造系统用户名。

## 9. 本章总结

本次修改让时间线更易读、事件顺序可预测，并统一缩短了人员部门路径。数据库仍保留稳定工号，前端仍能兼容没有姓名的历史事件，未引入额外外部接口请求。
