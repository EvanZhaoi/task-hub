# 40 - 桌面端页面检查

## 1. 本章目标

本章记录 TaskHub 第一期桌面端页面的实际浏览器检查结果，确认核心页面在公司常用桌面宽度下没有明显溢出、遮挡或无法操作的问题。

本轮仅检查现有功能，不增加业务规则，也不修改数据库结构。

## 2. 检查环境

| 项目 | 本轮配置 |
| --- | --- |
| 浏览器 | Microsoft Edge（Chromium） |
| 页面宽度 | 1440、1280、1024 像素 |
| 页面高度 | 900、800、768 像素 |
| 后端 | Laravel 本地开发服务器 |
| 数据库 | 独立验证数据库 `taskhub_verify` |
| 登录身份 | 本地临时 QA Session，不调用公司 SSO |
| 外部目录 | 使用本地临时缓存，不调用公司人员和付款账号接口 |

临时登录入口、验证数据和缓存只用于本轮检查，检查结束后均已删除，不属于生产代码。

## 3. 检查范围与结果

### 3.1 任务大厅

- 关键词、状态和复杂度筛选区在三个宽度下均未横向溢出。
- 任务卡片中的状态、复杂度、紧急标记和影响范围可以正常显示。
- 发布者、部门、截止时间、金额和投标数量保持稳定对齐。
- 多页数据可以显示统一分页控件。

### 3.2 发布任务弹窗

- 遮罩层能够隔离背景页面，弹窗打开后不能误点任务大厅的查询和重置按钮。
- Header 和 Footer 固定，中间表单区域可以独立滚动。
- 交付日期可以打开日历并选择日期。
- 招标截止时间可以选择日期，并输入任意合法小时和分钟。
- 付款账号可以按名称或 code 搜索，结果可选择，长文本不会撑破弹窗。
- 本轮没有提交表单，因此不会产生新的业务任务。

### 3.3 任务详情

- 返回链接保留来源列表的查询参数。
- 任务状态、复杂度、紧急标记和影响范围正常显示。
- 任务附件名称和链接可以显示。
- 投标记录默认保持紧凑，展开后可以查看方案和投标附件。
- 页面在 1024 像素宽度下无横向溢出。

### 3.4 我的任务

以下三个独立页面均完成检查：

- 我发布的：关键词、状态筛选、任务信息和分页正常。
- 我的投标：投标角色、报价、承诺日期、版本和分页正常。
- 执行任务：执行角色、最终交期、成员、成交金额和分页正常。
- 顶部“我的任务”菜单可以访问上述三个入口。

## 4. 浏览器诊断

检查期间浏览器 Console 没有发现 JavaScript error。三个桌面宽度下，页面根节点的内容宽度没有超过浏览器视口宽度。

## 5. 本轮结论

TaskHub 第一期现有桌面页面通过本轮检查，没有发现需要修改生产代码的布局或交互问题。

仍需在正式测试环境继续验证以下内容：

1. 公司 SSO 的真实登录、退出和 Token 生命周期。
2. 公司人员、付款账号、文件和 SMTP 接口。
3. 目标 MySQL 8 环境的最终兼容性。
4. 公司实际显示器、浏览器策略和网络环境。
