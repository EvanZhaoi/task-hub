# 18-发布任务附件上传

## 本章目标

本章实现发布任务附件上传。

用户不再手工填写附件 ID，而是在发布任务弹窗中选择文件。浏览器会先把文件上传到 TaskHub 后端，Laravel 后端再携带当前登录人的 `accessToken` 调用总部文件上传接口：

```text
POST /file-operation/file/upload
```

总部上传成功后，TaskHub 只保存响应中的：

```text
data.id
data.name
```

注意：附件唯一标识是 `id`，不是 `fileId`。文件名使用总部返回的 `data.name`，不是浏览器本地文件名兜底。

## 学习目标

完成本章后，你应该理解：

- 为什么 React 不能直接调用总部上传接口。
- Laravel 如何接收浏览器上传的 `multipart/form-data`。
- Laravel HTTP Client 如何继续转发 multipart 文件。
- 为什么 `serviceKey` 必须来自后端配置。
- 为什么 TaskHub 同时保存附件 ID 和附件名称。

## 最终效果

发布任务附件流程：

```text
用户选择文件
↓
TaskAttachmentUploader 调用 /attachments/upload
↓
AttachmentController 获取当前 Session accessToken
↓
FileUploadClient 携带 Authorization: bearer {token}
↓
multipart/form-data 上传 file + serviceKey
↓
读取总部响应 data.id
↓
读取总部响应 data.name
↓
TaskHub 上传接口返回 { id, name }
↓
前端保存 [{ id, name }]
↓
发布任务时提交 attachments = uploadedFiles
↓
CreateTaskService 写入 attachment_ref.attachment_id / attachment_ref.attachment_name
```

## 每一步操作

### 第 1 步：增加文件服务配置

新增：

```text
config/file_operation.php
```

核心内容：

```php
<?php

return [
    // 总部文件服务基础地址，只放域名和公共前缀，例如 https://sso.example.com。
    'base_url' => env('FILE_OPERATION_BASE_URL'),
    // 总部文件上传接口 path，只写 path，不写完整 URL。
    'upload_path' => env('FILE_OPERATION_UPLOAD_PATH', '/file-operation/file/upload'),
    // 总部分配给 TaskHub 的文件服务标识，后端上传时作为 serviceKey 提交。
    'service_key' => env('FILE_OPERATION_SERVICE_KEY'),
    // 外部接口调用超时时间，避免上传请求长时间挂起。
    'timeout' => (int) env('FILE_OPERATION_TIMEOUT', 10),
    // 本地/测试环境可关闭证书校验；生产环境建议设置为 true。
    'verify_ssl' => filter_var(env('FILE_OPERATION_VERIFY_SSL', false), FILTER_VALIDATE_BOOLEAN),
];
```

`.env` 需要配置：

```env
FILE_OPERATION_BASE_URL=
FILE_OPERATION_UPLOAD_PATH=/file-operation/file/upload
FILE_OPERATION_SERVICE_KEY=
FILE_OPERATION_TIMEOUT=10
FILE_OPERATION_VERIFY_SSL=false
```

为什么这样设计：

- `base_url` 和 `upload_path` 分开，避免不同环境重复改完整 URL。
- `serviceKey` 是后端配置，不能写死在前端。
- `businessKey`、`modelKey` 当前没有业务需求，按本次要求不传。

### 第 2 步：封装总部上传 Client

`FileUploadClient::upload()` 接收：

- Laravel 已校验的 `UploadedFile`。
- 当前登录 Session 中的动态 `accessToken`。

关键代码：

```php
$request = Http::baseUrl($baseUrl)
    ->timeout((int) config('file_operation.timeout', 10))
    ->acceptJson()
    // 总部接口调用统一使用当前登录人的动态 accessToken。
    ->withHeaders(['Authorization' => 'bearer '.$accessToken])
    // attach() 会把请求转换为 multipart/form-data，并把 file 作为真实文件字段提交。
    ->attach(
        name: 'file',
        contents: fopen($file->getRealPath(), 'r'),
        filename: $file->getClientOriginalName(),
    );

$response = $request->post($uploadPath, [
    // serviceKey 必填，但必须来自后端配置，不能写死在 React 或 Controller。
    'serviceKey' => $serviceKey,
]);
```

注意：

- 这里不手动设置 `Content-Type`。
- Laravel HTTP Client 会自动生成 multipart boundary。
- 不打印 accessToken 到日志。

### 第 3 步：读取 data.id 和 data.name

`UploadedFileRef::fromPayload()` 中读取总部上传接口的完整响应：

```json
{
  "code": "",
  "data": {
    "id": "123",
    "name": "需求说明.pdf"
  },
  "msg": "",
  "timestamp": 0
}
```

关键代码：

```php
// 附件 ID 是总部文件服务的唯一标识，后续下载/预览使用它。
$id = $payload['data']['id'] ?? null;

// 附件名称用于 TaskHub 任务详情直接展示，避免为了显示文件名再调用总部文件列表接口。
$name = $payload['data']['name'] ?? null;
```

如果总部响应没有 `data.id` 或 `data.name`，直接抛异常。

这样可以避免两个问题：

- 把错误字段 `fileId` 当作附件 ID 保存。
- 只保存 ID，任务详情显示附件名时又必须调用总部文件 List 接口。

### 第 4 步：增加站内上传入口

路由：

```php
Route::middleware(EnsureSsoAuthenticated::class)->group(function (): void {
    // 附件先上传到 TaskHub 后端，再由后端携带当前登录 accessToken 转传到总部文件服务。
    Route::post('/attachments/upload', [AttachmentController::class, 'upload'])->name('attachments.upload');
});
```

Controller：

```php
public function upload(
    UploadAttachmentRequest $request,
    CurrentUserService $currentUser,
    FileUploadClient $files,
): JsonResponse {
    try {
        $uploadedFile = $files->upload(
            file: $request->file('file'),
            accessToken: $currentUser->accessToken(),
        );
    } catch (FileUploadException $exception) {
        throw ValidationException::withMessages([
            'file' => $exception->getMessage(),
        ]);
    }

    // 返回给 React 的结构保持扁平：{ id, name }。
    // 前端不需要知道总部接口的 code/msg/timestamp，也不再读取 file.id 这种二次包装。
    return response()->json($uploadedFile->toResponsePayload());
}
```

为什么 React 不直接调总部：

- React 运行在浏览器，不能接触后端 `serviceKey`。
- 总部接口需要当前登录 `accessToken`，TaskHub 已经统一把 token 保存在 Laravel Session 中。
- 后端调用总部接口不受浏览器 CORS 限制。

### 第 5 步：替换手工附件 ID 输入框

新增：

```text
resources/js/components/tasks/TaskAttachmentUploader.tsx
```

组件职责：

- 用户点击“选择文件”。
- 隐藏的 `<input type="file" multiple>` 打开文件选择器。
- 选择后立即 POST `/attachments/upload`。
- 上传成功后只保存 `{ id, name }`。
- 上传失败的文件不加入列表。
- 删除按钮只从本次表单中移除，不调用远程删除接口。

关键代码：

```tsx
const response = await fetch('/attachments/upload', {
    method: 'POST',
    credentials: 'same-origin',
    headers: {
        Accept: 'application/json',
        'X-CSRF-TOKEN': csrfToken(),
        'X-Requested-With': 'XMLHttpRequest',
        // 不要手动设置 Content-Type。
        // 浏览器会自动生成 multipart/form-data boundary。
    },
    body: formData,
});
```

上传接口返回值直接读取：

```tsx
// TaskHub 后端已经把总部响应转换成扁平结构：{ id, name }。
const uploadedFile = payload as UploadResponse | null;

if (!uploadedFile?.id || !uploadedFile.name) {
    throw new Error('文件上传成功响应缺少附件 ID 或名称。');
}
```

### 第 6 步：发布任务提交 attachments 数组

`Tasks/Index.tsx` 中维护上传成功的文件：

```tsx
const [uploadedAttachments, setUploadedAttachments] = useState<UploadedTaskAttachment[]>([]);
```

当上传列表变化时：

```tsx
function changeUploadedAttachments(files: UploadedTaskAttachment[]): void {
    setUploadedAttachments(files);
    // 上传接口已经返回总部文件 ID 和名称，发布任务时直接提交结构化数组。
    // 后端只保存 attachment_id / attachment_name，不保存总部完整响应。
    form.setData('attachments', files);
}
```

后端 `StoreTaskRequest::attachments()` 会按 `id` 去重，并保留第一次出现的 `name`。

### 第 7 步：数据库保存附件 ID 和名称

`attachment_ref` 只增加一个必要字段：

```sql
`attachment_name` VARCHAR(255) NOT NULL COMMENT '外部附件名称'
```

最终落库示例：

```text
owner_type      TASK
owner_id        任务 ID
attachment_id   123
attachment_name 需求说明.pdf
uploaded_by     当前登录人工号
```

为什么不保存总部完整响应：

- 当前任务详情只需要文件 ID 和文件名。
- 完整响应字段未来可能变化，保存全部会把外部系统细节扩散到 TaskHub。
- 下载/预览时只需要 `attachment_id`，到那一步再调用或拼接总部下载地址。

## 核心原理解释

### multipart/form-data 是什么

普通 JSON 请求适合传文本字段：

```json
{
  "title": "任务标题"
}
```

文件上传需要传二进制内容，所以浏览器会使用 `multipart/form-data`。它把请求体分成多个 part：

- 一个 part 是 `file` 文件。
- 一个 part 是 `serviceKey` 字符串。

### 为什么不设置 Content-Type

上传文件时，浏览器或 Laravel HTTP Client 会自动生成类似这样的请求头：

```text
Content-Type: multipart/form-data; boundary=----xxx
```

如果手动写 `Content-Type: multipart/form-data`，通常会缺少 boundary，服务端反而解析不了文件。

### accessToken 从哪里来

上传入口在受保护路由里：

```text
EnsureSsoAuthenticated
↓
CurrentUserService
↓
Session TOKEN_SESSION_KEY
↓
accessToken
```

React 不知道 token，也不需要知道 token。

## 与 Spring Boot 对照

| Laravel | Spring Boot | 说明 |
|---|---|---|
| `UploadAttachmentRequest` | `@Valid MultipartFile` 校验 | Laravel 用 FormRequest 集中校验 |
| `AttachmentController` | `@RestController` | 接收浏览器上传，返回 JSON |
| `UploadedFile` | `MultipartFile` | 表示浏览器上传到后端的文件 |
| `FileUploadClient` | WebClient / RestTemplate Client | 后端调用总部文件服务 |
| `Http::attach()` | MultipartBodyBuilder | 构造 multipart/form-data |
| `CurrentUserService` | SecurityContext / Session Service | 统一获取当前登录人和 token |

## 常见错误

### 1. File operation service key is not configured

原因：`.env` 没有配置 `FILE_OPERATION_SERVICE_KEY`。

处理：

```bash
php artisan config:clear
```

然后重新上传。

### 2. File upload response does not contain data.id / data.name

原因：总部响应结构不符合当前确认格式，或者接口返回了错误数据。

处理：

- 检查日志中的 `body_preview`。
- 确认字段是 `data.id` 和 `data.name`。
- 确认 ID 字段不是 `fileId`。

### 3. 419 CSRF token mismatch

原因：前端没有带 CSRF token，或者页面上的 meta token 过期。

处理：

- 确认 `resources/views/app.blade.php` 有 `<meta name="csrf-token">`。
- 确认前端请求带 `X-CSRF-TOKEN: csrfToken()`。
- 刷新页面后重试。

### 4. 上传后发布任务没有附件

排查：

- 前端上传列表中是否已经显示附件 ID。
- `changeUploadedAttachments()` 是否把 `files` 写入 `form.data.attachments`。
- 发布任务测试是否仍断言 `attachment_ref` 写入成功。

## 本章总结

本章只实现上传链路，不实现下载、预览、分片、进度条和远程删除。

当前设计保持 MVP 简单：

- 文件上传由独立 `FileUploadClient` 封装。
- Controller 不直接拼总部接口。
- React 不接触总部 token 和 serviceKey。
- 发布任务接口提交 `attachments: [{ id, name }]`。
- TaskHub 数据库保存附件 ID 和附件名称，不保存真实文件内容和总部完整响应。
