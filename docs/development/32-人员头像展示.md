# 32 - 人员头像展示

## 1. 本章目标

本章记录 TaskHub 的统一人员头像展示方案。头像 ID 来自本据点人员列表接口的 `eibPhoto`，不依赖 SSO 当前人员接口，也不为每个人单独请求人员接口。

## 2. 数据流程

```text
人员列表接口 eibPhoto
    ↓
PersonnelUser / Redis 人员缓存
    ↓
Controller 批量按工号映射 avatarId
    ↓
Inertia Props
    ↓
UserAvatar
    ↓
PERSONNEL_AVATAR_BASE_URL + avatarId
```

人员目录已经是任务大厅、投标成员和执行成员的数据来源。头像功能只在这些已有查询结果中增加 `avatarId`，不会循环调用外部接口。

## 3. 环境配置

```env
# 头像服务只提供 HTTP；末尾可以有或没有 /。
PERSONNEL_AVATAR_BASE_URL=http://avatar-server.example/path
```

`UserAvatar` 会清理前缀和 ID 之间重复的 `/`。当 TaskHub 页面也通过 HTTP 访问时，浏览器可以直接加载图片，图片流量不经过 PHP。

> 如果未来 TaskHub 升级为 HTTPS，浏览器可能拦截 HTTP 头像这类混合内容。届时应在 Nginx 层增加同域 HTTPS 反向代理和缓存，不建议让每张图片都占用 PHP 进程转发。

## 4. 统一组件

`resources/js/components/common/UserAvatar.tsx` 负责：

- 组合头像 HTTP 前缀和 `avatarId`。
- 使用 `loading="lazy"` 只加载进入可视区域的图片。
- 使用 `decoding="async"` 避免图片解码阻塞页面绘制。
- 头像 ID 为空或图片请求失败时，显示姓名第一个字符。
- 姓名为空时使用工号首字符，再没有数据时显示 `?`。

## 5. 展示位置

第一版只放在能帮助识别人员的关键位置：

1. 顶部当前登录用户。
2. 任务大厅每条任务的发布者。
3. 任务详情顶部的发布者。
4. 可见投标记录的主投标人和协作成员。
5. 选标或直接指派后的正式执行成员。

人员选择器、时间线和隐藏的投标记录暂不增加头像，避免一次渲染大量图片。

## 6. 验证

1. 配置 `PERSONNEL_AVATAR_BASE_URL`，并执行 `php artisan config:clear`。
2. 有 `eibPhoto` 的人员显示远程头像。
3. 没有 `eibPhoto` 的人员显示姓名首字符。
4. 将头像 ID 改为无效值，图片请求失败后仍应显示首字符。
5. 任务列表翻页时只加载当前页可见头像。

本功能不修改数据库结构，不保存图片文件，也不增加本地用户表。
