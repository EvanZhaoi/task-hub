# 37 - 任务影响范围与日期选择优化

## 1. 本章目标

本章完成两项发布任务体验改进：

1. 每个任务记录成果的预计影响范围：本部门、本 Division 或全公司。
2. 日期选择器增加月份和年份直接选择，并扩大前后月按钮点击区域。

影响范围是业务展示属性，不是权限配置。选择“本部门”不代表其他部门不能查看或投标，TaskHub 的可见性和操作权限仍由后端业务规则决定。

## 2. 最终效果

发布任务表单新增“影响范围”下拉框：

```text
是否紧急                         影响范围
[ ] 标记为紧急任务               [本部门 v]
                                  本 Division
                                  全公司
```

任务大厅、任务详情、“我发布的”和“执行任务”统一显示范围标签。

日期弹层顶部同时提供：

```text
[上一月大按钮] [月份下拉] [年份下拉] [下一月大按钮]
```

用户可以直接跨年、跨月，也可以继续使用箭头切换相邻月份。

## 3. 数据库设计

Task 表增加：

```sql
`impact_scope` VARCHAR(20) NOT NULL DEFAULT 'DEPARTMENT'
```

允许值：

| 数据库存储值 | 页面文案 | 含义 |
|---|---|---|
| `DEPARTMENT` | 本部门 | 成果主要供发布人所在部门使用 |
| `DIVISION` | 本 Division | 成果预计覆盖发布人所在 Division |
| `COMPANY` | 全公司 | 成果预计在全公司范围使用 |

没有为该字段增加索引。当前需求只需要保存和展示，尚无按影响范围筛选或统计的高频查询，提前增加索引没有实际收益。

### 3.1 全新数据库

直接执行最新的：

```text
database/schema.sql
```

### 3.2 已有数据库

在部署新代码前执行一次：

```bash
# 使用实际数据库名称替换 taskhub。
mysql -u 用户名 -p taskhub < database/patches/20261118_add_task_impact_scope.sql
```

补丁给历史任务写入默认值 `DEPARTMENT`，因此不会产生空值。该脚本只能执行一次，重复执行会提示字段已经存在。

## 4. 后端实现

`StoreTaskRequest` 校验提交值：

```php
// 影响范围是固定业务枚举，不能直接信任浏览器提交的任意字符串。
'impactScope' => [
    'required',
    'string',
    Rule::in(['DEPARTMENT', 'DIVISION', 'COMPANY']),
],
```

`CreateTaskService` 和 `CreateDirectTaskService` 都保存该字段，确保招标和直接指派两种发布方式行为一致：

```php
'impact_scope' => $validated['impactScope'],
```

创建事件的 `event_data` 也保存 `impactScope`，用于以后查看任务发布时的关键属性快照。

列表和详情 Controller 将数据库蛇形命名转换为前端驼峰命名：

```php
'impactScope' => $task->impact_scope,
```

## 5. 前端实现

业务类型集中在 `resources/js/types/task.ts`：

```ts
// 只允许使用与数据库 CHECK 约束一致的三个值。
export type TaskImpactScope = 'DEPARTMENT' | 'DIVISION' | 'COMPANY';
```

发布表单默认选择“本部门”，降低普通任务的操作成本。影响范围与紧急标记放在同一行，各占一半宽度；金额和复杂度仍单独保持一行，避免五个字段挤在狭窄列中。

`TaskAttributeBadges` 统一负责范围文案和样式，因此任务大厅、详情与个人工作页不会维护不同的映射规则。

## 6. 日期组件优化

项目继续使用已经安装的 `react-day-picker`，没有增加依赖。

`DatePicker` 传入：

```tsx
<Calendar
    // 同时显示月份和年份下拉框。
    captionLayout="dropdown"
    // 箭头放在下拉框两侧，键盘焦点顺序与视觉顺序一致。
    navLayout="around"
    // 使用中文月份、星期和无障碍文案。
    locale={zhCN}
    startMonth={startMonth}
    endMonth={endMonth}
/>
```

年份默认覆盖当前年前一年至未来十年；如果表单回填值超出范围，会自动扩展到该年份。

Calendar 基础组件将前后月按钮从 28px 扩大到 36px，并给图标添加 `pointer-events-none`。这样点击按钮背景、内边距或箭头本身都会触发切换，不再要求精确点中细小图标。

月份和年份使用原生 `select` 覆盖整个可见下拉区域，支持鼠标、键盘和系统原生选择行为。

手工检查：

1. 发布招标任务，分别选择三个影响范围并确认保存结果。
2. 发布直接指派任务，确认同样保存影响范围。
3. 在任务大厅、详情、“我发布的”和“执行任务”查看范围标签。
4. 打开期望交付日期，直接选择月份和年份。
5. 点击箭头按钮的空白区域而不只点图标，确认月份可以切换。
6. 打开招标截止时间，确认日期、小时和分钟仍可正常填写。

## 9. 常见错误

### 发布时报 `Unknown column impact_scope`

现有数据库尚未执行升级脚本。先执行 `database/patches/20261118_add_task_impact_scope.sql`，再重新发布任务。

### 页面提示影响范围格式不正确

检查前端提交值是否严格为 `DEPARTMENT`、`DIVISION` 或 `COMPANY`，不要提交中文文案。

### 日期下拉没有可选年份

确认 `DatePicker` 给 Calendar 传入了 `captionLayout="dropdown"`、`startMonth` 和 `endMonth`，并重新运行 Vite 构建。

## 10. 下一步

当前不增加影响范围筛选和统计。实际使用一段时间后，如果任务大厅确实需要按范围筛选，再补充查询条件并根据真实查询频率评估索引。
