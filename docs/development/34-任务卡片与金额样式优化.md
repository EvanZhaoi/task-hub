# 34 - 任务卡片与金额样式优化

## 1. 本章目标

本章记录任务大厅卡片的布局调整、预算与成交金额的统一视觉语义，以及 Phase 1 尚未实现状态的前端入口收敛。

本轮只修改展示层，不改变任务数据、状态枚举、后端筛选逻辑或数据库结构。

## 2. 涉及文件

- `resources/js/Pages/Tasks/Index.tsx`：任务大厅卡片布局和可见状态筛选。
- `resources/js/Pages/Tasks/Show.tsx`：任务详情金额样式。
- `resources/js/Pages/MyTasks/Published.tsx`：“我发布的”金额样式和状态入口。
- `resources/js/Pages/MyTasks/Assignments.tsx`：执行任务金额样式和状态入口。
- `resources/js/components/tasks/TaskAmountDisplay.tsx`：统一预算与成交金额的展示语义。

## 3. 任务大厅卡片布局

原卡片使用固定左、中、右三栏。发布者区域只有约 `13rem`，减去头像后部门名称可用宽度很小，即使先截取组织路径仍然难以阅读。

现在卡片改为：

```text
卡片头部：任务标题、状态标签                         金额
卡片正文：任务描述，最多两行
分隔线
底部信息带：发布者和部门    预计交付    招标截止    投标情况    查看详情
```

关键设计：

1. 标题和描述使用卡片完整宽度，不再被中间栏挤压。
2. 金额在头部右侧固定展示，方便用户纵向比较任务。
3. 发布者区域使用弹性宽度，部门名称最多显示两行。
4. 部门名称超出两行时省略，鼠标悬停可以查看完整简称。
5. 头像使用 `md` 尺寸，姓名使用 `text-sm + font-semibold`，避免头像或文字过度抢占任务标题的视觉层级。
6. 窄屏时头部和底部信息自动换行，不产生横向滚动。

## 4. 统一金额语义

任务预算与成交金额不能只依靠相近的文字颜色区分。新增 `TaskAmountDisplay` 后，同时通过标签、边框、背景和金额颜色表达业务含义。

### 4.1 任务预算

- 标签：`任务预算`
- 深灰金额：表示仍处于预算或招标阶段。
- 中性浅灰背景：不与状态标签、主操作争夺注意力。

### 4.2 成交金额

- 标签：`成交金额`
- 墨绿色金额：表示金额已经通过选标或直接指派确认。
- 低饱和淡绿色背景：与预算明显区分，但不使用过于鲜艳的颜色。

组件使用示例：

```tsx
<TaskAmountDisplay
    // 后端已经根据任务阶段返回应展示的金额。
    amountLabel={task.amountLabel}
    // BUDGET 使用中性色，FINAL 使用已确认的绿色语义。
    amountType={task.amountType}
/>
```

当前统一应用于：

- 任务大厅。
- 任务详情。
- “我发布的”。
- 执行任务。

“我的投标”展示的是投标人的报价，不是任务最终成交金额，因此继续使用投标方案自身的紫色语义，不强行套用成交金额样式。

## 5. 暂时隐藏未实现状态入口

Phase 1 当前已支持的任务阶段是：

- 招标中。
- 待选标。
- 进行中。
- 已流标。

任务完成和任务取消业务尚未开发，因此暂时从以下前端筛选入口隐藏：

- 任务大厅状态快捷项。
- “我发布的”状态快捷项。
- 执行任务状态快捷项。

本次没有删除：

- `COMPLETED`、`CANCELLED` 状态类型。
- 数据库 CHECK 约束。
- 后端查询和状态映射。
- `TaskAttributeBadges` 对历史数据的兼容展示。

这样可以避免用户点击尚未形成完整业务闭环的入口，同时保证未来开发交付、完成和取消功能时不需要重新设计数据结构。

## 6. 验证步骤

在项目根目录执行：

```bash
# 检查所有 TS/TSX Props 和组件调用是否正确。
npm run typecheck

# 验证 Tailwind 样式可以进入生产构建。
npm run build

# 确认前端调整没有影响现有 Laravel 业务流程。
php artisan test
```

页面检查：

1. 任务大厅标题、金额、描述和底部信息带层级清晰。
2. 发布者头像不过大，姓名与部门字号协调。
3. 长部门名称可以显示两行，超出后省略，悬停可以看到完整简称。
4. 预算为中性灰色，成交金额为低饱和绿色。
5. 任务详情、“我发布的”和执行任务金额样式一致。
6. 状态筛选中不再出现“已完成”和“已取消”。

## 7. 本章总结

任务卡片从固定三栏改为信息自然流动的头部、正文和底部信息带，解决部门名称空间不足问题。金额样式现在具有统一且明确的业务语义，尚未实现的状态入口也已暂时收敛，但底层扩展能力仍然保留。
